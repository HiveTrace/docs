Политики задаются отдельно для каждого приложения. С их помощью можно включить встроенную защиту HiveTrace, создать собственные правила для запросов пользователей.

## Как открыть настройки политик

1. В боковом меню выберите **Приложения**.
2. Откройте нужное приложение, нажав на карточку или на название приложения в зависимости от выбранного вида отображения.
3. Наведите на вкладку **Защита**.
4. Нажмите на **Цензурирующие политики**.

![Переход в настройки политик](../../../../assets/img/policies-redirect-4-4.webp)

В верхней части страницы отображаются название, id, описание (при наличии) приложения. Рядом с ID доступна кнопка копирования. На странице также доступна ссылка `«Назад к приложениям»`, которая ведёт в раздел `Приложения`.

## Редактирование приложения

![Редактирование приложения](../../../../assets/img/policies-edit-app-4-4.webp)

1. Нажмите `«Редактировать»`.
2. Измените нужные поля.
3. Нажмите `«Сохранить»`.

## Удаление приложения

![Удаление приложения](../../../../assets/img/policies-delete-app-4-4.webp)

1. Нажмите `«Удалить»`.
2. Подтвердите удаление в окне подтверждения.

Удаление необратимо. Сначала убедитесь, что интеграционный трафик остановлен или перенаправлен и связанные API-токены больше не используются.

## Профиль

Если профиль выбран, отображается его название. Если профиль не выбран — действуют индивидуальные настройки. При изменении настроек защиты приложения оно отвязывается от профиля, а текущие настройки переходят в индивидуальные.

Обновить профиль можно на странице: 
1. Нажмите кнопку `«Профиль»`.
2. Выберите нужный профиль из списка. Поле поиска помогает быстро сократить список.
3. Подтвердите привязку профиля к приложению в окне подтверждения.

![Профиль на странице политики](../../../../assets/img/policies-profile-4-4.webp)

## HiveTrace Guardrail

HiveTrace Guardrail — встроенная защита от небезопасных запросов. Проверки включаются независимо для каждого направления:

- **Ввод** — проверять сообщения, поступающие от пользователя к модели.
- **Вывод** — проверять ответы модели перед передачей пользователю.

После изменения переключателей нажмите **Сохранить**. Кнопка **Сбросить** отменяет несохранённые изменения и возвращает значения по умолчанию.

![Раздел HiveTrace Guardrail](../../../../assets/img/policies-overview-4-4.webp)

## Пользовательские политики

Пользовательская политика проверяет запросы пользователей по заданной инструкции — промпту. Таблица **Правила модели** показывает название и промпт каждой политики.

![Таблица пользовательских политик](../../../../assets/img/policies-custom-list-4-4.webp)

Доступные действия:

- **Добавить политику** — открыть форму создания правила.
- Флажок в строке — выбрать политику; флажок в заголовке выбирает все видимые строки.
- **Удалить выбранные** — удалить отмеченные политики. Кнопка активируется после выбора хотя бы одной строки.
- **Настройка колонок** — выбрать столбцы, отображаемые в таблице.
- Меню **⋮** в строке — отредактировать или удалить конкретную политику, а также для работы с историей версий политики: в ней можно просмотреть предыдущие версии и восстановить нужную.
- **Строк на странице**, **Предыдущая** и **Следующая** — управлять пагинацией.

### Создание, редактирование и тестирование политики

Нажмите **Добавить политику** или выберите редактирование в меню **⋮**. В форме укажите:

1. **Название** — понятное имя правила.
2. **Промпт** — инструкция, по которой валидируются пользовательские запросы.
3. **Ввод** — включить применение политики к входящим сообщениям.

Справа расположено окно тестирования. Введите проверочный запрос и нажмите кнопку отправки:

- красное сообщение со значком предупреждения означает, что политика обнаружила нарушение;
- зелёное сообщение со щитом означает, что запрос прошёл проверку.

Проверяйте как запрещённые, так и допустимые формулировки. После проверки нажмите **Сохранить**; **Отмена** закрывает форму без сохранения.

![Редактирование и тестирование пользовательской политики](../../../../assets/img/policies-custom-edit-test-4-4.webp)

## Проверка результата

После сохранения настроек отправьте тестовый запрос через подключённое приложение. Результаты срабатываний доступны в **Аналитике сессий**: откройте запись и перейдите в разделы **Цензоры** или **Конфигурация валидации**. Для синхронных защищённых интеграций нарушение также может привести к блокировке запроса.

## Доступ к странице

Для редактирования приложения из шапки нужны права:

- Область **Приложения** — уровень доступа не ниже `«Редактирование»`.

Для удаления приложения из шапки нужны права:

- Область **Приложения** — `Полный` уровень доступа.

Для просмотра настроек Guardrail и пользовательских политик нужны права:

- Область **Приложения** — уровень доступа не ниже `«Чтение»`;
- Область **Политики приложения** — уровень доступа не ниже `«Чтение»`.

Для редактирования настроек Guardrail и пользовательских политик нужны права:

- Область **Приложения** — уровень доступа не ниже `«Чтение»`;
- Область **Политики приложения** — уровень доступа не ниже `«Редактирование»`.

Для удаления пользовательских политик нужны права:

- Область **Приложения** — уровень доступа не ниже `«Чтение»`;
- Область **Политики приложения** — `Полный` уровень доступа.

Для обновления профиля приложения нужны права:

- Область **Приложения** — уровень доступа не ниже `«Редактирование»`;
- Область **Политики приложения** — уровень доступа не ниже `«Редактирование»`;
- Область **Профили защиты** — уровень доступа не ниже `«Чтение»`.

Если у пользователя нет доступа для просмотра страницы, отображается страница `403 - Нет доступа`.
