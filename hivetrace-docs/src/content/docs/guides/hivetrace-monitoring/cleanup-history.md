Страница **«История очисток»** показывает результат фонового удаления сообщений из хранилища. Она нужна, чтобы убедиться, что операция завершилась, и проверить, сколько пользовательских сообщений и ответов LLM было удалено.

## Как открыть страницу

Перейдите по ссылке из уведомления о запущенной очистке. Администратор также может открыть прямой адрес `/cleanup-history`.

![История фоновых операций очистки](../../../../assets/img/cleanup-history-4-3.webp)

## Поля таблицы

- **Удалено сообщений пользователей** — количество удалённых пользовательских запросов.
- **Удалено ответов LLM** — количество удалённых ответов моделей.
- **Статус** — текущее состояние фоновой операции. Пока операция выполняется, итоговые счётчики могут изменяться.
- **Создано** — дата и время запуска операции.
- **Пагинация** — переключает страницы истории, если операций больше, чем помещается в таблице.

## Как проверить результат очистки

1. Найдите последнюю операцию по времени создания.
2. Дождитесь её завершения. Не запускайте повторную очистку, пока текущая операция выполняется.
3. Сверьте оба счётчика с ожидаемым объёмом данных. Они могут различаться: сессия не обязательно содержит равное количество запросов и ответов.
4. Если операция завершилась ошибкой, зафиксируйте время запуска и обратитесь к администратору платформы для проверки журналов backend и ClickHouse.

История отображает агрегированный результат и не позволяет восстановить удалённые сообщения.
