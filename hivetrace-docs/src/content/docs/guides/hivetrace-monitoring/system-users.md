Раздел **Системные пользователи** используется для управления учетными записями, которые могут входить в интерфейс HiveTrace, и для назначения им ролей. Откройте его по значку пользователя с плюсом в боковом меню.

![Общий вид страницы системных пользователей](../../../../assets/img/system-users-table-4-4.webp)

## Необходимые права

| Действие | Область | Мин. доступ |
|---|---|---|
| Просмотр страницы | `Операторы системы` | `Чтение` |
| Создание пользователей | `Операторы системы` | `Редактирование` |
| Активация и деактивация системных пользователей | `Операторы системы` | `Редактирование` |
| Удаление пользователей | `Операторы системы` | `Полный` |
| Просмотр действующих назначений пользователей | `Операторы системы` | `Чтение` |
| | `Роли и назначения` | `Чтение` |
| Назначение ролей пользователям, их отзыв | `Операторы системы` | `Чтение` |
| | `Роли и назначения` | `Полный` |

Если у пользователя нет доступа для просмотра страницы, отображается страница `403 - Нет доступа`.

## Таблица пользователей

Каждая строка соответствует одной учетной записи. Таблица содержит следующие данные:

| Колонка | Описание |
| --- | --- |
| **Пользователь** | Имя и email системного пользователя |
| **Активен** | Текущее состояние учетной записи |
| **Последний вход** | Дата и время последней успешной авторизации; отображается дефис, если входов еще не было |

Нажмите **Настройка колонок**, чтобы показать или скрыть доступные поля таблицы. Меню **⋮** в конце строки открывает действия с выбранной учетной записью; состав действий зависит от прав текущего пользователя.

В нижней части таблицы можно выбрать число строк на странице и перейти на предыдущую или следующую страницу. Недоступная кнопка навигации отображается серым.

## Добавление пользователя

1. Нажмите **Добавить нового пользователя**.
2. Заполните обязательные поля формы.
3. Нажмите **Добавить**.

![Форма добавления системного пользователя](../../../../assets/img/system-user-create-4-4.webp)

В форме добавления системного пользователя заполняются:

- `Имя Пользователя` - отображаемое имя учетной записи;
- `Email` - email для входа;
- `Пароль` - пароль для входа в систему.

Все поля отмечены звездочкой и обязательны. Значок глаза в поле **Пароль** показывает или скрывает введенное значение. Кнопка **×** закрывает форму без создания пользователя.

После успешного добавления новая учетная запись появляется в таблице. Сама по себе новая учетная запись еще не дает доступ к разделам интерфейса: для доступа нужно назначить роль. Благодаря роли пользователь получает доступ к нужным действиям в пределах своей области действия: роль задаёт, какие операции ему разрешены, а какие остаются недоступными.

## Активация и деактивация учётной записи

1. Найдите учётную запись и откройте меню **⋮**.
2. Выберите **Деактивировать** для активной записи или **Активировать** для неактивной.
3. Дождитесь уведомления об успехе и проверьте значение в колонке **Активен**.

![Меню действий системного пользователя](../../../../assets/img/system-user-actions-4-4.jpg)

Действие применяется сразу, без отдельного окна подтверждения. Деактивация закрывает пользователю доступ к платформе, но сохраняет учётную запись и назначения ролей. Чтобы вернуть доступ, активируйте запись снова; доступные разделы по-прежнему определяются назначенными ролями.

## Удаление учётной записи

1. Найдите учётную запись и откройте **⋮ → Удалить**.
2. Проверьте окно подтверждения и нажмите **Удалить**. Чтобы отменить действие, закройте окно.
3. Дождитесь уведомления об успехе и убедитесь, что запись исчезла из таблицы.

![Подтверждение удаления системного пользователя](../../../../assets/img/system-user-delete-confirm-4-4.jpg)

На этой странице нет действия восстановления удалённой записи. Для временного прекращения доступа используйте **Деактивировать**.

Для активации и деактивации нужен уровень **Операторы системы → Редактирование**, для удаления — **Полный**. Без соответствующего права действие не отображается. Нельзя деактивировать или удалить собственную запись, а также лишить систему последнего активного системного администратора. Если действие отклонено, прочитайте уведомление об ошибке: допустимое действие должен выполнить другой администратор, либо сначала нужно обеспечить наличие другого активного администратора с системной ролью.

## Назначить роль системному пользователю

1. Найдите учетную запись в списке системных пользователей.
2. Раскройте строку системного пользователя.
3. Выберите роль.
4. Выберите `Тип области`. Назначить роль можно на всю систему, на группу приложений или на определённое приложение. 
5. Выберите `Область`, если она требуется для выбранного типа области.
6. Нажмите `Добавить назначение`.

![Назначение роли системному пользователю](../../../../assets/img/system-user-assign-a-role-4-4.webp)

После сохранения системный пользователь получит права, описанные выбранной ролью, в выбранной области действия. При успешной выдаче назначения интерфейс показывает уведомление `Назначение выдано`. Если системный пользователь уже находится в системе, после изменения прав ему может потребоваться обновить страницу.

Наличие права у пользователя само по себе не означает, что он получит доступ к конкретному приложению. Право должно действовать именно на это приложение — то есть, входить в назначение, область которого покрывает данное приложение.

## Просмотреть действующие назначения системного пользователя

1. Найдите учетную запись.
2. Раскройте строку системного пользователя.
3. Посмотрите таблицу `Действующие назначения`.

![Просмотр назначений системного пользователя](../../../../assets/img/system-user-assignments-4-4.webp)

В таблице видно, какие роли уже выданы системному пользователю, где они действуют, кто выдал назначение и когда оно было выдано. Если назначений нет, таблица покажет `Нет данных`.

У одного системного пользователя может быть несколько назначений. Права из разных назначений объединяются: отсутствие доступа в одной роли не отменяет разрешение из другой. Итоговые права пользователя определяются всеми его активными назначениями и их областями действия.

У действующего назначения есть действие `Отозвать`. Оно удаляет назначение роли у системного пользователя. После отзыва права, которые были получены только через это назначение, перестают действовать.

## Рекомендации по настройке ролей

- Создавайте роли под реальные рабочие задачи, а не под конкретных людей.
- Не выдавайте полный доступ, если системному пользователю достаточно просмотра.
- Используйте группы приложений для команд, которые работают с одинаковым набором приложений.
- Проверяйте итоговые права системного пользователя после изменения ролей.
- Удаляйте или отключайте лишние назначения, если системный пользователь больше не должен иметь доступ.
